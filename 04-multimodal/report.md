## Персональный финансовый советник

Telegram‑бот для учета доходов и расходов с использованием LLM/VLM (через OpenRouter или Ollama) и поддержкой транзакций из текста, изображений и (архитектурно) голосовых сообщений.

---

## Вариант задания

- **Версия:** расширенный вариант
- **Что реализовано сверх базового:**
  - Обработка изображений (чеки, скриншоты) через vision‑модель
  - Поддержка локальных моделей через Ollama
  - Архитектура для транскрибации голосовых сообщений и извлечения транзакций из них

---

## Технологический стек

- **Язык и рантайм**
  - Python 3.11+
  - `uv` — управление зависимостями и виртуальным окружением

- **Telegram**
  - `aiogram 3.x` — фреймворк для Telegram Bot API (polling)

- **LLM / VLM слой**
  - Библиотека `openai` (AsyncOpenAI) как единый клиент
  - Провайдеры:
    - OpenRouter (облако, на этапе ранних итераций)
    - Ollama (локальный/облачный сервер) — **текущий рабочий вариант**
  - Модели (через Ollama):
    - `qwen2.5:7b-instruct` — текстовая модель для обработки сообщений
    - `qwen3-vl:8b-instruct` — vision‑модель для изображений

- **Speech‑to‑Text (архитектурно)**
  - `transcription.py`:
    - `transcribe_voice_openai()` — OpenAI Whisper API (альтернативный провайдер, сейчас недоступен по региону)
    - `transcribe_voice_yandex()` — Yandex SpeechKit (основной выбранный провайдер)
    - `transcribe_voice()` — универсальный фасад с выбором провайдера через `TRANSCRIPTION_PROVIDER`

- **Модели данных и валидация**
  - `pydantic` — модели `Transaction`, `TransactionResponse`, перечисления типов транзакций

- **Конфигурация и промпты**
  - `python-dotenv` — загрузка `.env`
  - Текстовые/визуальные системные промпты в `prompts/`

## Облачный сервер и Ollama

- **Провайдер и окружение**
  - Облачный сервер с установленным Ollama
  - Доступ к Ollama по адресу `http://195.209.210.20:11434/v1`

- **Используемые модели Ollama**
  - `qwen2.5:7b-instruct` — основная текстовая модель для извлечения транзакций
  - `qwen3-vl:8b-instruct` — vision‑модель для анализа чеков и скриншотов

- **Интеграция**
  - Бот использует AsyncOpenAI клиент с `OPENAI_API_KEY=ollama` и `OPENAI_BASE_URL=http://195.209.210.20:11434/v1`
  - Переключение между OpenRouter и Ollama — через переменные окружения `.env`

## Основные вызовы и решения

1. **Региональная блокировка OpenAI**
   - Проблема: регистрация в OpenAI и использование Whisper API невозможны из‑за блокировки региона.
   - Решение: архитектурно сохранить поддержку Whisper, но **перенести основной фокус на Yandex SpeechKit** и/или локальные решения.

2. **Настройка прав доступа в Yandex SpeechKit**
   - Проблема: ошибки `PermissionDenied / UNAUTHORIZED` при обращении к API, несмотря на настройку ролей.
   - Решение: реализовать поддержку Yandex SpeechKit в коде, улучшить обработку ошибок и **временно отключить голосовую обработку в продакшене**, сохранив весь код и документацию до момента корректной настройки прав в Yandex Cloud.

3. **Переход с OpenRouter на Ollama для LLM/VLM**
   - Проблема: необходимость стабильно работать без внешнего облака, используя локальные модели.
   - Решение: вынести `OPENAI_BASE_URL` и имена моделей в `.env`, настроить AsyncOpenAI на Ollama endpoint и **подобрать совместимые модели** (`qwen2.5:7b-instruct` и `qwen3-vl:8b-instruct`).

4. **Поддержка изображений через vision‑модели**
   - Проблема: различия в поддержке `response_format` (`json_schema`, `json_object`) и форматах vision‑вызовов между провайдерами.
   - Решение: реализовать адаптивную логику: сначала пытаться structured output через `json_schema`/`json_object`, при ошибках — падать в «ручной» JSON‑режим с осторожным парсингом и расширенным логированием.

5. **Поддержка голосовых сообщений без ломки UX**
   - Проблема: технически реализованный voice‑пайплайн нельзя полноценно включить из‑за провайдера STT.
   - Решение: добавить в `handlers.py` обработчик голосовых сообщений, который **пока отвечает понятным сообщением** о временной недоступности голоса и предлагает использовать текст/изображения, чтобы пользовательский опыт не страдал.

## Что я узнал нового

1. **Практическая интеграция LLM/VLM через единый AsyncOpenAI клиент**  
   Как безопасно и прозрачно переключать провайдеры (OpenRouter ↔ Ollama) и модели через конфигурацию, сохраняя один и тот же код запросов.

2. **Структурированный вывод (structured output) с Pydantic и `response_format`**  
   Как задавать JSON‑схемы из Pydantic‑моделей, обрабатывать частичные/невалидные ответы и обеспечивать устойчивый парсинг.

3. **Интеграция локальных моделей через Ollama в реальном боте**  
   Как поднимать отдельный LLM/VLM‑сервер, управлять моделями (`pull`, проверка тегов) и диагностировать ошибки (404, connection error) в боевом режиме.

4. **Проектирование voice‑пайплайна с несколькими STT‑провайдерами**  
   Как спроектировать модуль транскрибации так, чтобы можно было легко переключать провайдера (Yandex/OpenAI/локальный Whisper) и при этом иметь единый интерфейс `transcribe_voice()`.

5. **Практика graceful degradation в чат‑боте**  
   Как сделать так, чтобы при недоступности части функциональности (голос) бот продолжал работать с другими типами сообщений и честно сообщал пользователю о статусе, не ломая общий сценарий.

## Краткий итог

Проект «Персональный финансовый советник» реализован как Telegram‑бот, который:
- стабильно работает с текстом и изображениями через локальные модели Ollama,
- имеет полностью реализованную архитектуру для обработки голосовых сообщений,
- использует AI‑driven подход для разработки кода и документации,
- готов к демонстрации как пример практической интеграции LLM/VLM и (архитектурно) STT в финансовом помощнике.
